## E. 本轮我新发现的一处真实脆弱点（建议关注，非阻塞）

**rootless 包内 plist 指向 rootful 路径，依赖 postinst 改写才能工作。**

```
线上 rootless 包内 var/jb/Library/LaunchDaemons/com.ziyan.framecap.plist：
  <string>/bin/sh</string>
  <string>/usr/lib/ziyan/bin/ziyan_framecap_wrap.sh</string>   ← rootful 路径！
  该 plist sha256 = c7360c52…（= 未改写版）
  固化后的正确版（postinst 重写）应为 b4d6ae70…（t1 实测）

设备实测（.53 rootless）：
  /usr/lib/ziyan/bin/ziyan_framecap_wrap.sh          → No such file or directory
  /var/jb/usr/lib/ziyan/bin/ziyan_framecap_wrap.sh   → 存在
```

- 含义：rootless 机的 launchd 若在 postinst 改写**之前**（或被跳过时）加载该 plist，`ProgramArguments` 指向不存在的路径 → `com.ziyan.framecap` 必然启动失败。
- 现状不阻塞（`.112` 已证 postinst 会改写为 `06e322ac…`/`b4d6ae70…`），但**「正确性依赖维护脚本」这一脆弱点是真实的**，与 §A2 的保留意见同源。
- 建议：让 rootless 包的 plist 在打包期就写成 `$JB` 路径（现在是运行时改写），可同时消除该脆弱点与 postinst 未执行时的隐患。
