一、设计原则
--------------------------------------------------------------------------------
1. 游戏包名不写死进工程 Filter
   - ZiYanDefense 仅注入：com.apple.UIKit + com.ziyan.ziyan（+ Executable ZiYan）
   - 任意第三方 UIKit App（含任意游戏）均可获得防御 Hook
   - 具体游戏 Bundle ID 仅作手工/脚本「测试样本」，写在 DEVICE_RULES / 测试脚本，
     不得进入 ZiYanDefense.plist

2. 分层（与开源工具能力对齐，禁止抄专有实现）
   | 层 | 模块 | 作用 | 是否动 AFC |
   |----|------|------|------------|
   | App 内伪装 | ZiYanDefense | 指纹 + 路径/环境/URL/dyld 名 Hook（对标 Shadow essential） | 否 |
   | 桌面图标 | ziyan_fscloakd 改名 *.ziyan_desk_hidden + IconShield 软 Hook | 开 App 会话隐藏越狱商店等图标 | 否 |
   | USB/爱思 | 不注入 afc2d/afcd/lockdownd；冷启只还原历史残留 | 爱思保持系统原生 AFC | 禁止破坏 |

3. 威胁模型澄清
   - 爱思助手：电脑端 USB → AFC/AFC2，不是游戏进程
   - 游戏公司：沙盒内检测（stat/NSFileManager/URL/dyld…），一般不能用 AFC
   - 故：防游戏 = 加强 Defense；防爱思读全盘 = 动 AFC（与爱思可用冲突，已废弃）

二、ZiYanDefense（App 内）
--------------------------------------------------------------------------------
注入：UIKit 进程；ctor 排除 SpringBoard / backboardd / 多数 com.apple.* 系统 App

指纹字段（defense_fingerprint.plist，关 App 保持；冷启清除）：
  model / systemVersion / name / idfv / lanIP / wanIP

Essential Hook 面（8-69，对标 Shadow essential 思路，自主实现）：
  C：stat / lstat / access / open / fopen
      getenv（DYLD_INSERT_LIBRARIES / _MSSafeMode / DYLD_LIBRARY_PATH /
             DYLD_FRAMEWORK_PATH → NULL）
      _dyld_get_image_name（越狱 dylib 路径伪装）
      sysctlbyname(hw.machine/hw.model) / uname / getifaddrs(en*)
  ObjC：UIDevice model/systemVersion/name/identifierForVendor
        NSFileManager fileExistsAtPath: / fileExistsAtPath:isDirectory:
        UIApplication canOpenURL:（cydia/sileo/zbra/filza 等 scheme → NO）

越狱路径针（节选）：Cydia/Sileo/Filza/NewTerm、MobileSubstrate、TweakInject、
  /var/jb、ellekit、procursus、dopamine…；永不对 /var/mobile/Media/ZiYan 撒谎

生命周期：
  - 开 ZiYan App：生成/加载指纹，弹「子砚 · 防御伪装信息」（独立 Alert Window）
  - 关 App：指纹文件可保留；cleanup dirty；不杀 AFC
  - 冷启/断电：BootRecovery 清指纹 + cleanup=clean；下次开 App 重生并弹框
  - AI：ZiYanDefenseAI 监控 bypass 触发与延迟退出 Toast（见 SECURITY_AI.md）

状态文件（必要，统一 /var/mobile/Media/ZiYan/ZYCV/res/）：
  defense_fingerprint.plist     — 假指纹持久（关 App 可保留；冷启清）
  defense_fp_info.txt           — App 信息框文案
  defense_status.txt            — 验收快照 active/hooks
  defense.log                   — 防御运行日志
  cleanup_flag（dirty/clean）   — 会话脏/净标记
  defense_bypass_trig.txt       — 验收：写入触发 AI 证据
  defense_break.flag            — 验收：突破判定
  defense_shutdown_trig         — 验收：触发完整恢复
  （旧顶层 Media/ZiYan/defense_* 会自动迁移到 ZYCV/res）

三、桌面越狱图标
--------------------------------------------------------------------------------
主路径（root 守护 ziyan_fscloakd v871+）：
  - session +（进程存活 | Media/var 心跳≤12s | 宽限 6 拍）→ 改名隐藏
  - 确认僵死后才清会话并还原；心跳 Media 双写（修 .53 立刻还原）
  - 无 session（关程序/杀进程/冷启）→ 改回并 uicache
辅路径：SpringBoard ZiYanIconShield（isIconVisible / SBIconView / ListModel）
保留：com.ziyan.ziyan 永不隐藏

四、AFC / 爱思（硬约束）
--------------------------------------------------------------------------------
- ZiYanFsCloak.dylib：Filter 指向不存在 Bundle，零注入
- ZiYanSetFsCloak：空操作并清历史伪装标志
- fscloakd：仅还原 *.ziyan_cloaked 与桌面 *.ziyan_desk_hidden；禁止 rename afc2d、
  禁止 kill lockdownd
- 历史教训：动 afc2d → .166 Media 错误码 13、.53 爱思转圈、afc2d 崩溃

六、手工回归清单（SECURITY_AI）
--------------------------------------------------------------------------------
A. App 未开：爱思可连；桌面有越狱商店/Filza 等图标
B. 打开 ZiYan：弹防御伪装信息；数秒内越狱图标消失（子砚保留）

E. 任意第三方游戏/App（非写死名单）：前台时可抽查假型号/越狱路径探测失败
   （测试样本可用设备上任意已装游戏，不要求工程内写死 Bundle ID）
